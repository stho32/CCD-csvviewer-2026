# User Stories — R00005: Ordnerstruktur der BL nach Architektur-Gruppen schneiden

## Mehrwert

Wer `CsvViewer.BL` öffnet, sieht die Architektur statt einer Liste technischer Themen.
Neuer Code findet seinen Platz, ohne dass man das Architektur-Dokument daneben legen muss.
Für den Nutzer des Viewers ändert sich nichts — das ist die Bedingung, unter der der Umbau
als gelungen gilt.

## US1 — Architektur im Explorer erkennen

> Als Entwickler will ich beim Öffnen von `CsvViewer.BL` auf einen Blick die fachlichen Gruppen sehen, damit ich neuen Code ohne Nachdenken am richtigen Ort ablege.

### Szenario 1.1 — Fünf Ordner statt neun

- **Given** das Projekt `CsvViewer.BL` nach dem Umbau
- **When** ich sein Wurzelverzeichnis aufliste
- **Then** finde ich genau `Common`, `HostContracts`, `DocumentAcquisition`, `PagePresentation` und `Interaction`
- **And** keiner der alten Ordner `CommandLineArguments`, `Csv`, `IO`, `Logging`, `Navigation`, `Paging`, `Rendering`, `Viewer` existiert noch

### Szenario 1.2 — Eingabe-Pipeline liegt beisammen

- **Given** den Ordner `DocumentAcquisition`
- **When** ich seinen Inhalt betrachte
- **Then** liegen dort Argument-Auswertung, CSV-Parsing und das CSV-Datenmodell
- **And** ich kann den Weg von den Programmargumenten zum fertigen Dokument lesen, ohne den Ordner zu wechseln

### Szenario 1.3 — Namespace folgt dem Ordner

- **Given** eine beliebige Datei im Ordner `PagePresentation`
- **When** ich ihre Namespace-Deklaration lese
- **Then** lautet sie `namespace CsvViewer.BL.PagePresentation;`
- **And** sie ist file-scoped wie im gesamten Projekt

## US2 — Verträge an einem Ort

> Als Entwickler will ich alle Verträge, die der Host implementiert, in einem Ordner finden, damit die Grenze zwischen Geschäftslogik und Host-Anbindung sichtbar ist.

### Szenario 2.1 — Host-Verträge gebündelt

- **Given** den Ordner `HostContracts`
- **When** ich seinen Inhalt auflisten
- **Then** enthält er genau `IConsole.cs`, `IFileReader.cs` und `ILogger.cs`
- **And** zu jedem dieser drei Verträge existiert eine Umsetzung unter `CsvViewer/HostSpecific/`

### Szenario 2.2 — BL-interner Vertrag bleibt bei seiner Implementierung

- **Given** den Vertrag `ITableRenderer`, den kein Host implementiert
- **When** ich nach seiner Datei suche
- **Then** liegt er in `PagePresentation` neben `TableRenderer.cs`
- **And** nicht in `HostContracts`

## US3 — Verhalten unverändert

> Als Nutzer will ich, dass der Viewer sich nach dem Umbau exakt wie vorher verhält, damit ein reines Refactoring für mich unsichtbar bleibt.

### Szenario 3.1 — Anzeige unverändert

- **Given** eine gültige CSV-Datei mit elf Datenzeilen
- **When** ich `csvviewer datei.csv` aufrufe und mit `E` beende
- **Then** zeigt die erste Seite genau die ersten zehn Datenzeilen samt Menü
- **And** der Exit-Code ist 0

### Szenario 3.2 — Testsuite bleibt vollständig grün

- **Given** die Testsuite vor dem Umbau mit 92 Tests
- **When** sie nach dem Umbau läuft
- **Then** sind es weiterhin 92 Tests und alle laufen durch
- **And** an keinem Test wurde etwas ausser seinen `using`-Direktiven geändert

### Szenario 3.3 — Build ohne Warnungen

- **Given** eine bereinigte Projektmappe
- **When** ich sie vollständig neu baue
- **Then** meldet der Build 0 Warnungen und 0 Fehler
