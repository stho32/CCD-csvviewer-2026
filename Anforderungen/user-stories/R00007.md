# User Stories — R00007: Datenobjekte in Data-Unterordner

## Mehrwert

Wer einen Topic-Ordner öffnet, sieht die Arbeit und nicht das Beiwerk. Der Einstiegspunkt
steht allein, die Ergebnistypen eine Stufe tiefer. Für den Nutzer des Viewers ändert sich
nichts — das ist die Bedingung, unter der der Umbau als gelungen gilt.

## US1 — Einstiegspunkt auf einen Blick

> Als Entwickler will ich beim Öffnen eines Topic-Ordners sofort sehen, welcher Typ die Arbeit tut, damit ich nicht erst fünf Dateien öffnen muss.

### Szenario 1.1 — Operation steht allein

- **Given** den Ordner `DocumentAcquisition` nach dem Umbau
- **When** ich ihn im Solution Explorer aufklappe
- **Then** sehe ich auf oberster Ebene genau eine Datei: `CsvParser.cs`
- **And** daneben den Unterordner `Data`

### Szenario 1.2 — Datenobjekte liegen beisammen

- **Given** den Ordner `DocumentAcquisition/Data`
- **When** ich seinen Inhalt betrachte
- **Then** enthält er `CsvDocument.cs`, `CsvHeader.cs`, `CsvRow.cs` und `CsvRowCollection.cs`
- **And** keiner dieser Typen enthält Logik über Konstruktion und Zugriff hinaus

### Szenario 1.3 — Kein Ordner für ein einzelnes Datenobjekt

- **Given** die Topics `Interaction` und `CommandLineInterpretation` mit je einem Datenobjekt
- **When** ich sie aufklappe
- **Then** liegen `NavigationCommand.cs` und `ViewerArguments.cs` weiterhin oben
- **And** es existiert dort kein Unterordner `Data`

### Szenario 1.4 — Namespace folgt dem Ordner

- **Given** die Datei `DocumentAcquisition/Data/CsvDocument.cs`
- **When** ich ihre Namespace-Deklaration lese
- **Then** lautet sie `namespace CsvViewer.BL.DocumentAcquisition.Data;`
- **And** sie ist file-scoped wie im gesamten Projekt

## US2 — Verhalten unverändert

> Als Nutzer will ich, dass der Viewer sich nach dem Umbau exakt wie vorher verhält, damit ein reines Refactoring für mich unsichtbar bleibt.

### Szenario 2.1 — Anzeige unverändert

- **Given** eine gültige CSV-Datei mit elf Datenzeilen
- **When** ich `csvviewer datei.csv` aufrufe und mit `E` beende
- **Then** zeigt die erste Seite genau die ersten zehn Datenzeilen samt Menü
- **And** der Exit-Code ist 0

### Szenario 2.2 — Testsuite bleibt vollständig grün

- **Given** die Testsuite vor dem Umbau mit 92 Tests
- **When** sie nach dem Umbau läuft
- **Then** sind es weiterhin 92 Tests und alle laufen durch
- **And** an keinem Test wurde etwas ausser seinen `using`-Direktiven geändert

### Szenario 2.3 — Build ohne Warnungen

- **Given** eine bereinigte Projektmappe
- **When** ich sie vollständig neu baue
- **Then** meldet der Build 0 Warnungen und 0 Fehler
